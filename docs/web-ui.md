# 人と管理者のための Web UI

人（管理者本人・グループのメンバー）がスマホやPCのブラウザから人間関係を見て、必要なら直すための画面。コードは [`server/hre_server/web.py`](../server/hre_server/web.py)。エージェント用の [MCP サーバー](mcp-server.md) と同じ DB・同じ権限・同じトークンを使う。

## できること

| 画面 | 内容 | 必要な権限 |
|---|---|---|
| ワークスペース一覧 | 読めるワークスペース（自分の＋共有されたもの） | read |
| 人の一覧 | 名前・SNS ハンドルで検索、種類で絞り込み | read |
| 人の一覧の並べ替え | 「自分との強さ順」でコアリスナーや親しい相手を上に出す | read |
| 人物カード | 識別子、情報（根拠・確度・記録者・出典つき）、関係とその文脈・強さ、つながりの強さ（強い順）、やり取りの履歴、この人に関する更新履歴 | read（機微情報は sensitive_read） |
| 出典 | エージェントが取り込んだ原文と、それにもとづく情報 | read |
| 更新履歴 | エージェントと人が何を記録したか | read |
| 編集 | 人・識別子・情報・関係の追加、名前変更、情報の取り消し、関係の終了、同一人物の統合、出典を「信頼済み」にする | write |
| フィールドマスター | エージェントが提案した項目の承認・統合・廃止 | 管理者 |
| AI 連携 | MCP の接続先 URL と AI ごとの接続手順、接続中のアプリの一覧と取り消し。OAuth の許可画面（`/connect`）もここ | 全員（自分の身元か自分が許可した接続。管理者は全部） |
| アクセス管理 | 利用者・エージェントの追加（トークン発行）、再発行、無効化、権限、ワークスペースの作成と共有 | 管理者 |
| 「自分」の指定 | 人物カードから、その人をワークスペースの視点の主（`is_self`）にする。`bootstrap` は管理者本人のノードを作らないので、owner ではこれで自分を決める | 管理者 |
| 完全削除 | 本人からの削除依頼などで、その人の記録を消す（表示名の入力で確認） | 管理者 |

- 人が書いた情報は「人間による書き込み」なので、人格設定（一人称・口調など）や管理者関係もここから書ける。エージェントは書けないまま
- 出典を「信頼済み」にすると、その出典を根拠にエージェントも人格フィールドを書けるようになる。決めるのは人
- 情報は上書きせず「取り消し」で履歴を残す（データモデルの方針どおり）
- JavaScript がなくても全操作できる（JS は入力欄の切り替えと確認ダイアログだけ）
- 識別子の値が `http://` か `https://` の URL なら、人物カードでリンクになる（新しいタブで開く）。ほかのアプリの画面に入れる値で、スタックチャン（[stack-chan](https://github.com/hardlitchi/stack-chan) のブリッジサーバー）は人をつなぐと識別子 `stackchan` にその人の画面の URL を書き、「スタックチャンで開く」として出る。スタックチャンの画面からは「HRE で開く」でこの人物カード（`/e/<id>`）に来る

## 関係の強さ

[データモデルの v1 案](data-model.md#5-関係の強さ密度クラスタは派生値) のとおり、0〜100 で表示する。

- **算出**: エージェントが記録したやり取りから。回数・深さ（挨拶 / 用件 / 深い会話）・新しさ（90日で約 1/3 に減衰）と、どちらから働きかけたか（互恵性）で決まる。話題に出ただけ（mentioned）は数えない
- **親しさ**: 関係に付けた「親しさ（主観）」1〜5 を 0〜100 に換算したもの。人もエージェントも付けられる
- **表示する強さ**: 親しさがあれば算出値との平均、なければ算出値
- 共通の知人の数と互恵性もあわせて出す

計算結果は `analysis_runs` / `pair_metrics` に保存し、そのワークスペースに書き込みがあったか 6 時間たった時点で、次に開いたときに計算し直す（定期ジョブは不要）。エージェントも MCP の `get_entity` で同じ値（各関係の `strength` と、強い順の `ties`）を受け取れる。

## グループ（推定）

強さを重みにした Louvain 法で、互いのつながりが濃い人たちをまとめる。ワークスペース画面の「グループ（推定）」で一覧でき、人物カードにはその人が入っているグループのほかのメンバーが出る。

- 「自分」は全員とつながっていて1つのグループに飲み込んでしまうので、除いて計算する
- 関係はあるがやり取りも親しさもないペアは弱い重み（0.1）でつなぐ
- 2人以上のグループだけを出す。密度（グループ内でつながっているペアの割合）と内部の平均の強さも出す
- 強さと同じタイミングで計算し直す。乱数の種を固定しているので、記録が変わらなければ結果も変わらない
- エージェントは MCP の `list_clusters` と、`get_entity` の `cluster` で受け取れる

## ログイン

`kind = human` の actor のトークンでログインする。エージェント用のトークンでは入れない。

最初の管理者は `hre-admin bootstrap` で作る（トークンが1度だけ表示される）。管理者がまだいないあいだは、ログイン画面にもこのコマンドが表示される。

```sh
hre-admin bootstrap ta                       # 管理者本人
hre-admin create-actor member-b human        # グループのメンバー
hre-admin grant member-b group read
```

管理者になったあとは、利用者の追加や権限の付与は Web UI の「アクセス」からもできる。

- ログインすると署名つき Cookie（HttpOnly・SameSite=Lax・Secure）で30日間保持する
- トークンを再発行・無効化すると、そのトークンで作ったセッションもすぐ使えなくなる
- 書き込みはすべて CSRF トークンつき。CSP で外部スクリプトを禁止し、原文はエスケープして表示する
- 個人情報が端末のキャッシュに残らないよう、HTML は `Cache-Control: no-store`

## 起動

```sh
cd server
pip install -e .
export DATABASE_URL=postgresql://hre:...@localhost/hre
export HRE_WEB_SECRET=$(openssl rand -hex 32)    # Cookie の署名鍵。変えると全員ログインし直し
HRE_ALLOWED_HOSTS=hre.example.com hre-web --host 127.0.0.1 --port 8001
```

時刻は `HRE_TIMEZONE`（既定 `Asia/Tokyo`）で表示する。

手元で http のまま試すときは `--insecure-cookies` を付ける（Secure 属性を外す。`HRE_INSECURE_COOKIES=1` でも同じ）。

### VPS で MCP サーバーと同じドメインに置く例（Caddy）

```
hre.example.com {
    handle /mcp* {
        reverse_proxy 127.0.0.1:8000
    }
    handle {
        reverse_proxy 127.0.0.1:8001
    }
}
```

スマホからは `https://hre.example.com/` を開いてトークンを1度入力する。ホーム画面に追加しておくとアプリのように使える。
